# 课件 → 交互式复习网页：可复用方法手册

> 适用：PPT、PDF、讲义、教材截图、老师给的复习提纲。
> 输出：单文件 HTML 复习网页；可离线打开，也可部署为公网静态站。
> 目标：能复习、能讲清、能做例题、能上考场，而不是把 PPT 搬成网页。

---

## 0. 开工前先定 4 件事

| 问题 | 选项 | 影响 |
|---|---|---|
| 范围 | 整门课 / 某一章 / 某一题型 / 考前冲刺 | 决定页面结构是「总复习」还是「专题页」 |
| 读者 | 自己复习 / 同学共享 / 老师检查 | 决定解释深度和术语量 |
| 输出 | 学习笔记 / 专题讲解 / 题库 / 一页速查 | 决定交互密度 |
| 验收 | 能复述 / 能做例题 / 能手机看 / 能打印 | 决定 QA 清单 |

**经验**：一次只做一种主形态。  
- 整门课：章 → 节 → 知识点 → 章末考点 → 总复习。  
- 一个题型：题目 → 为什么 → 分步计算 → 考场模板 → 标准答案。  
- 不要在同一页里既做全课程总览，又做某道题的逐步动画，会互相抢注意力。

---

## 1. 七阶段流水线

```text
0 资料清点
   ↓
1 提取（文字 + 图片 + 页码 + 公式）
   ↓
2 内容重构（章 → 节 → 知识点 → 例题/考点）
   ↓
3 信息架构（页面骨架、目录、阅读路径）
   ↓
4 UI 设计（设计变量、组件、响应式）
   ↓
5 交互与动画（步骤、点击、播放、静态总览）
   ↓
6 质检（结构、视觉、交互、多端、无障碍）
   ↓
7 发布（本地预览 → 公网/静态站）
```

每个阶段的退出标准：

| 阶段 | 做完的标志 |
|---|---|
| 0 | 知道要覆盖哪些章节/页码，输出形态已定 |
| 1 | 每页 PPT 的文字、图片、公式、例题都有来源记录 |
| 2 | 每个知识点都有「结论 + 为什么 + 怎么做 + 例子/易错」 |
| 3 | 不看 PPT 也能顺着网页读下去 |
| 4 | 手机和桌面都不挤、不裁切、不横向溢出 |
| 5 | 每个动画都能解释一个因果关系，且可暂停/回看 |
| 6 | 控制台无报错，链接全通，320px 也能看 |
| 7 | 有可访问 URL 或可直接发送的文件 |

## 2. 提取：PPT 往往比想象中难

### 2.1 不要只复制文字

很多课件页是**整页截图**或**公式图片**，`python-pptx` 只能读到图片对象，读不到文字。  
第 5 章第 87–89 页就是三张整页图片，必须先导出图片再看。

推荐提取顺序：

1. `python-pptx` 导出每页的文字、形状位置、图片。
2. 对纯图片页，导出 `slide.image.blob` 为 PNG，逐张查看。
3. 需要时用 LibreOffice / PowerPoint 把整页渲染成图，保留版式。
4. 公式、矩阵、流程图优先**重画**；重画不了再保留截图，并在网页里加文字说明。
5. 每页记录 `slide_no`，后面写「对应 PPT 第 X 页」。

### 2.2 提取脚本（可复用）

```python
from pptx import Presentation
import os

pptx = r"D:\课件\第5章 词向量技术.pptx"
out = r"D:\课件\_extract"
os.makedirs(out, exist_ok=True)
prs = Presentation(pptx)

for i, slide in enumerate(prs.slides, 1):
    texts = []
    for j, sh in enumerate(slide.shapes):
        text = getattr(sh, "text", "").strip()
        if text:
            texts.append(f"[{j}] {text}")
        if sh.shape_type == 13:  # PICTURE
            img = sh.image
            fn = os.path.join(out, f"slide{i:03d}_{j}.{img.ext}")
            open(fn, "wb").write(img.blob)
    if texts:
        print(f"\n===== SLIDE {i} =====")
        print("\n".join(texts))
```

### 2.3 提取时的坑

- **编码乱码**：PPT 文本可能是 GBK/旧字体，终端显示乱码；不要凭乱码猜内容，直接看图片或原 PPT。
- **公式是图片**：`text` 为空不代表没内容；先看 `shape_type`。
- **同一页多个图片拼版**：第 88 页由 5 张图组成，要按位置排序阅读，不要按文件序号。
- **表格/矩阵被拆成多个文本框**：以图片为准重画。
- **页码 ≠ 幻灯片序号**：在内容表里同时记录「PPT 页码」和「文件第 N 页」。

## 3. 内容重构：从「页」变成「知识点」

### 3.1 三级结构

```text
章（Chapter）
  └─ 节（Section）
       └─ 知识点（Knowledge Point，简称 KP）
            ├─ 一句话结论
            ├─ 为什么（原理/动机）
            ├─ 怎么做（步骤/公式）
            ├─ 例子
            └─ 易错点/考试提示
```

### 3.2 每个 KP 的最小内容

一个合格的知识点卡片至少包含：

| 字段 | 说明 |
|---|---|
| 标题 | 一句话说清「讲什么」 |
| 学习要求 | 掌握 / 理解 / 了解 |
| 结论 | 加粗的一句话，复习时只看这句也能回忆 |
| 为什么 | 动机、直觉、与前后知识的联系 |
| 怎么做 | 步骤、公式、流程 |
| 例子 | 至少一个可验算/可对照的例子 |
| 易错 | 学生最可能错的地方 |
| 来源 | PPT 页码 / 教材页码 |

> 如果某个 KP 写不出「为什么」，说明还没真正理解，先补资料再写网页。

### 3.3 把 PPT 短句改成可读句

PPT 常见写法：

```text
• W=I
• Q=K=V=I
• A=K^TQ
```

网页要写成：

> 因为三个变换矩阵都是单位矩阵，单位矩阵乘任何矩阵都不改变它，所以 Q=WQ·I=I，K、V 同理。

### 3.4 对比与流程要表格化

适合表格化的内容：

- 概念对比（语义 vs 语用、FMM vs RMM、CBOW vs Skip-Gram）
- 算法步骤（规则/ML/DL/LLM）
- 参数/公式汇总
- 易混点（按列 vs 按行 Softmax）

适合流程化的内容：

- 算法执行顺序
- 数据流（输入 → 编码 → 分类）
- 计算步骤（矩阵乘法、Softmax）

### 3.5 考试型内容单独建模

对「计算题/证明题/流程题」，不要只写知识点，要写：

1. **题目原文**（条件、要求、分值）
2. **已知条件翻译**（维数、矩阵、约定）
3. **分步计算**（每步为什么、怎么写）
4. **考场模板**（答题纸上按什么顺序写）
5. **检查清单**（维度、归一化、符号、舍入）
6. **标准答案**（完整矩阵/结果）
7. **易错点**（方向、行列、公式约定）

## 4. 信息架构：读者怎么走

### 4.1 总复习页的骨架

```text
顶栏（目录/动画/回到顶部）
侧边目录（章 → 节 → 知识点）
主内容
  ├─ 课程信息 / 学习要求
  ├─ 第 1 章
  │    ├─ 章首（目标、本章框架）
  │    ├─ 1.1 节
  │    │    ├─ 知识点卡片
  │    │    ├─ 图表/动画
  │    │    └─ 例题/易错
  │    ├─ …
  │    └─ 章末考点速览
  ├─ 第 3 章 …
  └─ 全课程总复习（对比表 + 一句话主线）
```

### 4.2 专题页的骨架

```text
Hero（这是什么题、多少分、几步）
题目卡（条件 + 要求 + 分值）
先记约定（3–5 张卡）
四步交互（步骤条 + 讲解 + 可视化 + 详情）
考场模板（得分动作 + 检查清单）
易错点
标准答案（矩阵 + 7 行答卷 + 复制/打印）
```

### 4.3 目录规则

- 三级：章 → 节 → 知识点。
- 默认只展开当前章/当前节，避免侧栏越滚越长。
- 滚动监听：当前章/节/知识点高亮；只展开当前路径。
- 点击章/节：滚动 + 展开；点击小三角：只折叠/展开。
- 深链接：`#k3-2-1` 能直接定位；加载后校正一次，避免布局变化导致偏移。
- 移动端：抽屉式目录，点条目后自动关闭。

### 4.4 阅读节奏

- 每屏一个主信息块。
- 长表格、长清单放到折叠面板里。
- 每个 KP 之间留 20–28px 间距；每节之间 48px；每章之间 80–96px。
- 重要结论用 `mark` 或加粗，但一屏不超过 2–3 处。
- 每章末尾给「核心考点速览」，让读者能快速回看。

## 5. UI 设计系统

### 5.1 设计变量（直接复用）

```css
:root{
  --bg:#f3f6fa; --surface:#fff; --surface2:#eef3f8; --surface3:#e2e9f1;
  --ink:#172431; --muted:#5c6b7c; --faint:#8795a5;
  --line:#dce5ee; --accent:#315b8a; --accent2:#4d7fb3; --accent-soft:#e8f0fa;
  --gold:#a56b12; --gold-soft:#fdf2da; --gold-line:#ecd3a0;
  --green:#2a7255; --green-soft:#e5f4ec; --green-line:#bfe0cf;
  --red:#a94535; --red-soft:#fdece8;
  --shadow:0 1px 2px rgba(20,35,52,.05),0 18px 40px -26px rgba(20,35,52,.32);
  --r:16px;
}
```

深色模式用同一组语义变量覆盖，不要在组件里写死颜色。

### 5.2 颜色语义

| 颜色 | 用途 |
|---|---|
| 蓝 `--accent` | 结构、章节号、主按钮、链接 |
| 金 `--gold` | 考试重点、分值、提示、选中格 |
| 绿 `--green` | 正确、通过、检查项、输出 |
| 红 `--red` | 易错、风险、错误级联 |
| 灰 `--muted/--faint` | 辅助信息、标签、注释 |

### 5.3 字体与排版

- 中文：`system-ui, -apple-system, "PingFang SC", "HarmonyOS Sans SC", "Microsoft YaHei", sans-serif`
- 数字/公式/矩阵：`ui-monospace, "Cascadia Code", Consolas, monospace`
- 正文 15–16px，行高 1.75–1.8。
- 章节标题 `clamp(22px, 3vw, 32px)`，Hero `clamp(30px, 4.4vw, 52px)`。
- 数字用 `font-variant-numeric: tabular-nums`，矩阵列才对齐。

### 5.4 布局

- 内容最大宽度 1020–1180px；两侧留白比卡片阴影更重要。
- 桌面：侧栏 302px + 主内容 1020px；或单栏 1180px 的专题页。
- 平板：≤1200px 侧栏改抽屉，主内容全宽。
- 手机：单栏；卡片 padding 14–16px；表格/矩阵允许横向滑动。
- 断点建议：`1200 / 1120 / 940 / 760 / 640 / 480 / 360`，按实际组件调，不要迷信固定值。

### 5.5 组件清单

| 组件 | 用途 | 关键点 |
|---|---|---|
| 章首 | 章节入口 | 章号、标题、一句话导语、目标 |
| KP 卡 | 知识点 | 图标 + 标题 + 正文；不要每张都大圆角 |
| 表格 | 对比/参数 | 外层 `overflow-x:auto`；`th` 不换行；数字对齐 |
| 公式块 | 公式 | 等宽、可横向滚动；不要用图片公式 |
| 流程步骤 | 算法/步骤 | 可点击步骤 + 上一步/下一步 + 圆点 |
| 折叠面板 | 长内容 | 用 `grid-template-rows:0fr/1fr` 动画 |
| 图示 | 结构/流程 | 内联 SVG；文字用 `text-anchor` 对齐 |
| 动画演示 | 动态过程 | 播放/暂停/上一步/下一步/重置/静态总览 |
| 矩阵 | 线代计算 | CSS Grid + 括号；格子可点击 |
| 提示块 | 重点/难点/易错 | 语义色 + 图标 + 短标题 |
| 考点速览 | 章末复习 | 两列卡片 + 锚点链接 |
| 考试模板 | 计算题 | 得分动作 + 检查清单 + 标准答案 |

### 5.6 卡片与层次

- 页面背景 `--bg`，卡片 `--surface`，卡片内嵌区域 `--surface2`。
- 阴影要轻：`0 18px 40px -26px`，不要又黑又糊。
- 边框 1px `--line`；圆角 12–18px。
- 一张卡片只做一个层级；嵌套不要超过 3 层。
- 表格不要套在窄卡片里；宽表用单独的全宽容器。

### 5.7 响应式铁律

1. 不允许页面级横向滚动。局部宽内容用 `overflow-x:auto`。
2. 所有 `display:flex` 的行都要考虑 `flex-wrap`。
3. 固定宽度矩阵在小屏要允许卡片内横向滑动，或缩小单元格。
4. 长标题、长按钮文字要测 320px。
5. 表格 `table-layout:fixed` + 百分比列宽，避免最后一列被裁。
6. 图片/SVG 用 `max-width:100%`；图示文字多时，宁可横向滑动，不要缩到看不清。

## 6. 动画：只为解释，不为炫技

### 6.1 动画的 5 种正当用途

1. **顺序**：算法步骤、计算流程（第 1 步 → 第 2 步）。
2. **因果**：改一个输入，哪一块结果跟着变。
3. **定位**：当前讲到矩阵的哪一行/哪一列/哪个格子。
4. **对比**：正确 vs 错误、前向 vs 逆向、按列 vs 按行。
5. **状态**：播放/暂停/重置/静态总览。

> 如果一个动画删掉后不影响理解，就删掉。

### 6.2 常用动画模式

| 模式 | 实现 | 适用 |
|---|---|---|
| 滚动渐入 | IntersectionObserver + `.reveal` | 长页面分段阅读 |
| 步骤流程 | `.fs.on` + 上一步/下一步 | 算法步骤 |
| 标签页 | `.step-tab.active` + `.step-panel` | 4 步专题 |
| 播放器 | `setInterval` + `step` + `render()` | SVG 演示 |
| 静态总览 | `static=true`，一次画完整状态 | 复习/打印 |
| 单元格高亮 | 加 `.hl/.col-hl/.row-hl/.dim` | 矩阵计算 |
| 进度条 | `width = (step+1)/n` | 多步讲解 |
| 折叠 | `grid-template-rows:0fr → 1fr` | 长内容 |

### 6.3 时间与节奏

- 面板切换：250–350ms。
- 高亮/颜色变化：150–250ms。
- 步骤自动播放：1.5–5s/步；数学计算题建议 3–5s。
- 不要自动播放一打开就动；默认停在第 1 步。
- 自动播放到末尾自动停，不循环（或明确提供循环按钮）。
- `prefers-reduced-motion: reduce` 时关闭动画，直接显示静态/全部内容。

### 6.4 状态机（避免动画 bug）

每个演示至少维护：

```js
{
  step: 0,
  total: 5,
  mode: 'fwd' | 'rev',
  static: false,
  timer: null
}
```

规则：

- 切换步骤前先 `stop()`，避免多个定时器叠加。
- 切 tab 时重置 `step=0`。
- 离开当前步骤时清理该步骤的计时器。
- 播放到末尾：`step = -1` 再 `+1` 实现循环，或直接停。
- `static` 模式不启动定时器；`play()` 里先判断 `static`。
- 每次 `render()` 先清空 SVG/DOM（`innerHTML=''`），避免旧元素残留。

### 6.5 静态总览

每个动画都应该有「静态总览」：

- 把最终状态一次性画完整；
- 让读者能截图/打印/回看；
- 不依赖计时器；
- 静态总览里的文字要能独立读懂。

### 6.6 性能

- 只动 `transform` 和 `opacity`，不要动 `width/height/top`。
- SVG 内联，不加载外部图片。
- 一个页面 10–20 个 SVG 没问题；不要 100+ 个动画同时跑。
- 滚动监听用 `requestAnimationFrame` 节流。
- 内容高度变化（折叠/演示）后用 `ResizeObserver` 重算滚动监听位置。

## 7. 交互设计

### 7.1 原则

- **可点的地方要像可点**：hover、focus、cursor、选中态。
- **点了要有反馈**：高亮、详情文字、进度变化。
- **不要藏关键内容**：折叠可以，但不能默认全部隐藏。
- **不要用 hover 才能看的内容**：手机没有 hover。
- **键盘可用**：Tab 能到按钮，Enter/Space 能触发，方向键可切步骤。

### 7.2 高价值交互

| 交互 | 价值 |
|---|---|
| 点击矩阵格子 → 显示点积/除法 | 把「结果」变成「过程」 |
| 点击列 → 高亮整列 + 列和 | 讲清按列 Softmax |
| 点击 O 格子 → 高亮 I 行 + A′ 列 | 讲清行选择/加权 |
| 步骤 tab + 上一步/下一步 | 控制节奏 |
| 自动演示 + 暂停 | 先看整体，再回看 |
| 静态总览 | 复习/打印 |
| 折叠「详细推导」 | 防止文字墙 |
| 复制标准答卷 | 考前直接背/打印 |
| 打印/存 PDF | 线下复习 |

### 7.3 目录交互

- 章/节标题点击：滚动 + 展开；
- 小三角点击：只折叠；
- 滚动时只展开当前路径；
- 当前项加 active；
- 移动端点条目后关闭抽屉；
- 深链接加载后校正位置；
- 不要所有章节默认全展开。

### 7.4 可访问性

- 按钮用 `<button>`，链接用 `<a>`。
- `aria-selected`、`aria-controls`、`role=tab/tabpanel`。
- 焦点样式 `:focus-visible`。
- 详情区 `aria-live="polite"`。
- 图片/SVG 有 `role="img"` + `aria-label`。
- 颜色不是唯一信息：正确/错误同时用文字/图标。

## 8. 考试型专题页：怎么讲「为什么这样算」

### 8.1 页面顺序

1. **题目原文**：条件、要求、分值。
2. **先记约定**：列向量/行向量、矩阵方向、Softmax 方向、是否缩放。
3. **分步计算**：每一步「为什么 → 怎么做 → 结果」。
4. **可点击验证**：点格子看来源。
5. **考场模板**：答题纸上写什么、顺序、分值。
6. **检查清单**：维度、归一化、符号、舍入。
7. **易错点**：方向反、按行/列、exp 当成矩阵指数。
8. **标准答案**：完整矩阵 + 可复制文本。

### 8.2 「为什么」怎么写

不要写「根据公式可得」，要写：

- 这个公式的**几何/语义直觉**是什么？
- 维度为什么是这样？
- 如果换成另一种写法，会差在哪？
- 这一步在考试中对应哪个得分点？

例：

> 为什么 A=KᵀQ？  
> 因为每个 token 是列向量，K 是 3×4、Q 是 3×4；Kᵀ 是 4×3，乘 Q 得到 4×4。A 的第 (i,j) 项就是第 i 个 key 与第 j 个 query 的点积。

### 8.3 计算题的「可验证」设计

- 所有中间矩阵都展示，不只给最终答案。
- 点每个格子能看到它由哪几项相加/相乘。
- 数字保留 4 位小数，但注明「用未舍入值计算」。
- 维度链写出来：`3×4 → 4×4 → 3×4`。
- 最后给「7 行答卷」，可直接抄/背。

### 8.4 评分点映射

| 步骤 | 答题纸上的动作 | 分值 |
|---|---|---|
| 1 | 写 I、Q/K/V、维度 | 3 |
| 2 | 写 A=KᵀQ、矩阵 | 3 |
| 3 | E、列和、A′ | 6 |
| 4 | O=VA′、矩阵 | 3 |

页面里的步骤条、分值标签、考场模板要与这个表一致。

### 8.5 公式约定必须显式声明

同一个注意力机制，可能有两种写法：

- 列向量：`A = KᵀQ`，按列 Softmax，`O = VA′`
- 行向量：`A = QKᵀ`，按行 Softmax，`O = A′V`

**两种都对，但不能混用。** 页面要写明采用哪一种，并提醒「考试以题目给定公式为准」。

## 10. 技术实现：单文件网页

### 10.1 为什么单文件

- 离线可用，发给同学不会掉 CSS/JS。
- 不需要构建、不需要服务器。
- 便于版本管理和部署。
- 60–350KB 都是可接受范围。

### 10.2 基本结构

```html
<!DOCTYPE html>
<html lang="zh-CN">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <meta name="color-scheme" content="light dark">
  <title>…</title>
  <style>/* 全部 CSS */</style>
</head>
<body>
  <header class="topbar">…</header>
  <main>…</main>
  <script>/* 全部 JS */</script>
</body>
</html>
```

### 10.3 数据驱动矩阵

不要手写 4×4 的 16 个格子。用数组 + 渲染函数：

```js
const A = [[2,1,1,2],[1,2,1,2],[1,1,2,2],[2,2,2,3]];

function renderMatrix(el, data, opts={}) {
  el.style.setProperty('--cols', data[0].length);
  el.innerHTML = data.flatMap((row, i) =>
    row.map((v, j) =>
      `<button class="mcell" data-i="${i}" data-j="${j}">${v}</button>`
    ).join('')
  ).join('');
}
```

优点：改数字只改数组；点击事件用事件委托；样式统一。

### 10.4 步骤引擎

```js
let step = 0;
const panels = [...document.querySelectorAll('.step-panel')];
const tabs = [...document.querySelectorAll('.step-tab')];

function showStep(n) {
  step = Math.max(0, Math.min(panels.length - 1, n));
  tabs.forEach((t, i) => {
    t.classList.toggle('active', i === step);
    t.setAttribute('aria-selected', String(i === step));
  });
  panels.forEach((p, i) => p.classList.toggle('active', i === step));
  progress.style.width = ((step + 1) / panels.length * 100) + '%';
}
```

### 10.5 SVG 图

- `viewBox` 固定，`width:100%;height:auto`。
- 文字用 `text-anchor="middle"` 或明确的 `start`。
- 箭头用 `<marker>`；颜色用 CSS 变量。
- 线条/文字不要贴边；留 8–12px 安全区。
- 复杂图先画在纸上/白板上，再写坐标。

### 10.6 目录与滚动监听

- 目录从 DOM 自动生成，避免手写 60 个链接。
- 用 `IntersectionObserver` 做渐入；滚动监听用 `requestAnimationFrame`。
- 内容高度会变（折叠、演示、图片加载）→ `ResizeObserver` 重算位置。
- 点击目录后平滑滚动；用 `scroll-margin-top` 处理固定顶栏。

### 10.7 无 JS 回退

```html
<noscript>
  <style>
    .reveal{opacity:1!important;transform:none!important}
    .toc{display:none}
    main{margin-left:auto!important}
  </style>
</noscript>
```

## 13. 常见 bug 模式（这个项目踩过的坑）

### 13.1 图示被错误嵌进 flex 容器

**现象**：图表被压成一条窄列、文字挤压、页面出现巨大空白。  
**原因**：`<div class="fig">` 被放进了 `.case-h`、`.box-h`、`.tbl-title` 这类 `display:flex` 的标题容器，且没有闭合。  
**修复**：把图表移出标题容器，作为 `.kp-body` 的直接子元素；标题只放图标 + 文字。

**检查**：

```python
for c in ['case-h','kp-head','fold-head','box-h','tbl-title']:
    for el in root.xpath(f'//*[contains(@class,"{c}")]'):
        for f in el.xpath('.//*[contains(@class,"fig")]'):
            print("BAD", c, f.get('id'))
```

### 13.2 动画引擎选错了 SVG

**现象**：演示区空白，页头 15×15 的小图标被塞进巨大图形。  
**原因**：`root.querySelector('svg')` 选中了 `.fig-head` 的图标，而不是 `.demo-stage svg`。  
**修复**：`root.querySelector('.demo-stage svg')`。

### 13.3 SVG 里写 `<sub>` / `<sup>`

**现象**：公式文字散落、跑到画布左下角、排版错乱。  
**原因**：SVG `<text>` 不认 HTML 的 `<sub>`，浏览器会把文本节点拆开。  
**修复**：用 Unicode 下标（`vₜ + vₛ + vₚ`）或 SVG `<tspan baseline-shift="sub">`。

### 13.4 目录没有知识点

**现象**：侧栏只有章/节，没有知识点链接。  
**原因**：TOC 从 `h4[id]` 生成，但知识点 id 在 `.card.kp[id]` 上，`h4` 没有 id。  
**修复**：从 `.card.kp[id]` 生成，取内部 `h4` 文字。

### 13.5 滚动监听位置过期

**现象**：目录高亮错位，点击后当前项不对。  
**原因**：页面初始化时算了一次位置，之后演示/图表/折叠改变高度。  
**修复**：`ResizeObserver` 监听 `main`，节流后重算；章节标题也纳入监听。

### 13.6 侧栏越滚越长

**现象**：滚动一遍后所有章节/小节都展开，当前章被挤出视野。  
**原因**：滚动监听只 `add('open')`，从不关闭。  
**修复**：每次当前项变化时，先关闭所有 `.toc-ch.open/.toc-sec.open`，再只展开当前路径。

### 13.7 深链接被平滑滚动抢走

**现象**：打开 `#s3-2` 后停在半路。  
**原因**：浏览器原生 hash 滚动 + CSS `scroll-behavior:smooth` + JS 校正互相竞争。  
**修复**：`html{scroll-behavior:auto}`；点击时用 `behavior:'smooth'`；hash 加载时用 `behavior:'instant'` 校正一次。

### 13.8 最终步骤反而变淡

**现象**：分词演示最后一步所有字都变灰。  
**原因**：`covered` 把已消费字符全部 dim，最终步没有排除。  
**修复**：`done = static || !!final`，最终步不再 dim。

### 13.9 矩阵卡片被裁切

**现象**：手机/窄屏时最后一列数字被切掉，页面没有横向滚动但内容看不见。  
**原因**：4 列固定宽度 + 标签 + padding 超过卡片；或 answer grid `minmax(250px)` 在 320px 下溢出。  
**修复**：
- 小屏减小 `--cw`（如 48–52px）；
- `.mat-body{overflow-x:auto}`；
- answer grid `minmax(290px,1fr)` + ≤360px 单列；
- 表格 `table-layout:fixed`。

### 13.10 CSS 覆盖 SVG 属性

**现象**：`fill="none"` 不生效，窗口框盖住词节点。  
**原因**：CSS 类 `.sv-box{fill:var(--surface)}` 优先级高于 SVG presentation attribute。  
**修复**：用专用类（`.sv-window{fill:none}`）或 inline `style`。

### 13.11 行列约定混用

**现象**：A 算出来是转置，Softmax 方向反，O 不对。  
**原因**：列向量约定 `A=KᵀQ` 与行向量约定 `A=QKᵀ` 混用。  
**修复**：在页面顶部/步骤 2 显式声明约定；检查 Softmax 是按列还是按行；考试以题目为准。

### 13.12 舍入误差

**现象**：最终 O 的最后一列 0.8251，但显示值相加得 0.8252。  
**原因**：中间值四舍五入后再相加。  
**修复**：用未舍入值计算，显示 4 位；页面注明「末位差 0.0001 属舍入」。

### 13.13 外部依赖

**现象**：发给别人后样式丢失/公式不显示。  
**原因**：引用 CDN 字体、KaTeX、图片。  
**修复**：系统字体、内联 SVG、手写公式/矩阵；单文件零依赖。

### 13.14 顶栏遮住锚点标题

**现象**：点目录后标题被固定顶栏盖住。  
**修复**：`[id]{scroll-margin-top:calc(var(--tbh) + 20px)}`。

### 13.15 深色模式对比度

**现象**：深色下按钮白字配浅蓝底、看不清。  
**修复**：深色模式单独覆盖强调色按钮的文字色/背景，别只改 `--accent`。
